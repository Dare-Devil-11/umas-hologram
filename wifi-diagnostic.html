Signal & Environment
0/5
✓
Check RSSI signal strength
Hold Option + click WiFi icon in menu bar. RSSI worse than −70 dBm = weak. Ideal: −50 or better. Noise below −85 is good.
/System/Library/PrivateFrameworks/Apple80211.framework/Versions/Current/Resources/airport -I | grep -E "SSID|RSSI|noise|channel"
✓
Scan for channel congestion
Many networks on your channel = interference = drops. Look for crowded channels and change your router to an empty one.
/System/Library/PrivateFrameworks/Apple80211.framework/Versions/Current/Resources/airport -s
✓
Distance test — move 5 ft from router
Move your device close to the router and wait 10 min. If drops stop → signal/distance is the problem. Move back and it returns → confirmed.
✓
Check 2.4 GHz vs 5 GHz
5 GHz = faster but shorter range. If you're far from the router and on 5 GHz — switch to 2.4 GHz in your router settings or WiFi name.
networksetup -getinfo Wi-Fi
✓
Open macOS Wireless Diagnostics
Built-in Apple tool. Run it WHILE the drops happen — it logs the exact moment of disconnect. Save the report and share with support.
open /System/Library/CoreServices/Applications/Wireless\ Diagnostics.app

Router & Modem
0/4
✓
Ping your router gateway
If pings to the router drop → the problem is between you and the router, not the ISP. Packet loss >2% = router/WiFi issue.
ping -c 30 $(netstat -rn | grep default | head -1 | awk '{print $2}')
✓
Ping 8.8.8.8 — bypass DNS
Router pings fine but 8.8.8.8 drops = problem between your router and ISP. Check modem/coax/cable line.
ping -c 60 -i 1 8.8.8.8 | tail -5
✓
Power cycle modem + router
Unplug modem first, then router. Wait 30 sec. Plug modem back in, wait 60s, then plug router back in. Fixes memory leaks and stuck DHCP leases.
arp -a
✓
Check for IP address conflict
Two devices with same IP = one drops randomly. Compare your IP to the ARP table — no duplicate IPs should exist.
ipconfig getifaddr en0 && echo "---ARP Table---" && arp -a | grep -v incomplete

DNS
0/3
✓
Compare DNS speed — ISP vs Cloudflare
Slow DNS makes every page load pause even when bandwidth is fine. Under 50ms = good. Over 200ms = switch DNS.
time dig google.com @8.8.8.8 +short; time dig google.com @1.1.1.1 +short
✓
Flush DNS cache
Stale cache causes pages to fail even when the internet is live. Run this and retest immediately.
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder; echo "DNS flushed"
✓
Switch to Cloudflare DNS 1.1.1.1
Fastest fix if DNS is the issue — takes effect immediately, no reboot needed. Reverts on next DHCP renewal if you want to undo.
networksetup -setdnsservers Wi-Fi 1.1.1.1 8.8.8.8 && echo "DNS updated"

Mac / Driver
0/4
✓
Run networkQuality test
Built-in since macOS Monterey. Shows upload + download quality score + responsiveness. Low RPM score = drop-consistent issue.
networkQuality
✓
Check en0 interface errors
Non-zero ierr/oerr = driver or hardware fault on the WiFi card itself. Ipackets going up = traffic is flowing.
netstat -I en0 2 | head -10 && ifconfig en0 | grep -E "status|errors"
✓
Check preferred networks list
Mac auto-jumps between known networks. If an old network is nearby, your Mac silently switches — looks like a drop. Remove old networks.
networksetup -listpreferredwirelessnetworks en0
✓
Force renew DHCP lease
Expired DHCP lease = your IP changes mid-session = drops. This renews without fully disconnecting.
sudo ipconfig set en0 DHCP && echo "Lease renewed"

ISP / Line
0/3
✓
Traceroute — find which hop drops
Look for * * * rows. Hop 1 = your router. Hop 2-3 timing out = ISP problem, not yours. Screenshot this for the ISP support call.
traceroute -n 8.8.8.8
✓
Log drops for 5 minutes — save evidence
Run 300 pings (5 min). Results saved to Desktop. Show ISP your packet loss % — they cannot argue with a log file.
ping -c 300 -i 1 8.8.8.8 | tee ~/Desktop/ping-log.txt; tail -3 ~/Desktop/ping-log.txt
✓
Test wired ethernet — isolate WiFi vs ISP
Plug ethernet directly into router. If drops stop = WiFi hardware issue. If drops continue on ethernet = ISP/modem is the problem. This is the definitive split test.
